# SpeAnalyze 개요 (Updated)

문서 버전: 2026-05-11

구현 구조와 유지보수 규칙은 [STRUCTURE_GUIDE.md](STRUCTURE_GUIDE.md), [Program_Structure.md](Program_Structure.md)를 함께 참고한다.

## 1. SpeAnalyze가 해결하는 문제

실험 현장에서 반복적으로 발생하는 문제는 아래와 같다.

1. 카메라 소프트웨어가 제조사별로 분리되어 실험 흐름이 끊긴다.
2. 모터 정렬과 영상 확인이 분리되어 정렬 시간이 길어진다.
3. 획득과 분석이 분리되어 데이터 검증이 늦어진다.

SpeAnalyze는 이를 한 화면 흐름으로 통합한다.

1. 카메라 제어
2. 모터/스테이지 제어
3. 획득 및 저장
4. SPE 분석

---

## 2. 현재 기능 맵

현재 프로젝트는 메인 탭 기준으로 아래 기능을 제공한다.

| 영역 | 목적 | 핵심 결과 |
|---|---|---|
| Live | 실시간 영상/정렬 | 즉시 시각 피드백 + ROI/프로파일 |
| Acquisition | 배치 획득 | SPE 저장 및 후속 분석 연결 |
| Scan | 반복 스캔 | 자동화된 측정 루틴 |
| AutoFocus | Z 포커싱 자동화 | 포커스 품질 최대점 탐색 |
| Kinematic | 6축 좌표계 이동 | 기구학 기반 정렬 자동화 |
| Analysis | SPE 파일 분석 | 프로파일/히스토그램/비교 |
| DeepAlign (실험) | 통합 운용 시나리오 | 정렬-획득-분석 시퀀스 단축 |

참고: 운영 버전에 따라 노출 탭은 구성값으로 일부 숨김/고정될 수 있다.

---

## 3. 사용자 기준 운영 시나리오

가장 일반적인 운영 순서는 아래와 같다.

1. Live에서 카메라 연결 및 기본 노출/프레임 설정
2. ROI 지정 후 빔 상태 확인
3. 모터 또는 스테이지로 정렬 수행
4. Acquisition 또는 Scan으로 배치 획득
5. SPE 저장 결과를 Analysis에서 즉시 검증

핵심 포인트는 획득과 분석이 끊기지 않는 점이다.

---

## 4. 데이터 흐름 요약

1. 카메라 프레임 유입
2. 이미지 처리 파이프라인 적용
3. UI 반영 (뷰어/프로파일/히스토그램)
4. 선택 시 저장 (SPE/CSV/이미지)
5. Analysis 탭에서 재로딩 또는 자동 오픈

이 흐름은 워커 스레드와 UI 스레드를 분리하는 원칙 위에 동작한다.

---

## 5. 하드웨어/연동 관점

SpeAnalyze는 장비별 SDK 차이를 내부 계층에서 흡수한다.

1. 카메라 계층: HIKVISION, Picam, Simulated
2. 모터 계층: ACS, KIMM Z, Newport Picomotor
3. 파일 계층: SPE Reader/Writer

운영자는 UI에서 장비를 선택하지만, 코드 내부에서는 공통 인터페이스로 제어한다.
