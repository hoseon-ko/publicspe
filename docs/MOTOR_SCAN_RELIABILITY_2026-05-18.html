DeepAlign 스캔 워커 — Move-Done 검증 + Timeout 통합

2026-05-18 · 작업자: Claude (Opus 4.7) · 영역: 모터 제어 신뢰성

1. 배경 — 왜 손댔나

DeepAlign의 3개 스캔(Mirror / KIMM / ACS) 워커는 모두 mover.move(point) → settle(ms) → snap 루프를 돈다. 그런데 각 mover가 "이동 완료를 어떻게 보장하느냐"는 제각각이라 신뢰성에 격차가 컸다.

스테이지변경 전 상태위험도
Mirror (Picomotor 8742) 완료 확인 0, timeout 0
RelativeMove가 비동기 명령 enqueue 후 즉시 반환. settle 시간 내에 못 끝내면 블러 프레임, 영원히 안 멈춰도 워커는 모름.		 치명
KIMM Z ACK(5s)/DONE(30s) 이벤트 blocking + TimeoutError raise. 기본 동작은 견고. 단 timeout 상수 박힘. 경미
ACS 6축 wait_in_position_all(30s) 존재. 그러나
(a) 캐시 race — 명령 직후 wait 시작 시 moving=False로 즉시 반환 가능
(b) silent timeout — 만료 시 예외 없이 return		 중간

2. 변경 요약

3종 모두 동일한 신뢰성으로 통일: move 명령 후 반드시 완료 확인 후 settle/snap, 실패 시 명시적 TimeoutError, timeout 값을 사용자가 UI에서 조절 가능.

2.1 Picomotor — ADD wait_motion_done()

8742 SDK에 명시적 motion-done 쿼리가 없어 위치 안정성 폴링으로 대체: poll_ms=50 간격으로 GetPosition 호출 → 같은 값이 연속 stable_n=3회 관측되면 정지 판정. timeout_ms 만료 시 TimeoutError.

def wait_motion_done(self, motor: int, timeout_ms: int = 10000,
                     poll_ms: int = 50, stable_n: int = 3) -> None:
    deadline = time.perf_counter() + timeout_ms / 1000.0
    stable = 0
    last = None
    while True:
        ok, pos = self._cmdlib.GetPosition(self._key, self._master, motor, 0)
        if ok:
            if last is not None and pos == last:
                stable += 1
                if stable >= stable_n:
                    return
            else:
                stable = 1
            last = pos
        if time.perf_counter() >= deadline:
            raise TimeoutError(f"Picomotor M{motor} move timeout after {timeout_ms}ms")
        time.sleep(poll_ms / 1000.0)

2.2 KIMM — FIX done_timeout_s 사용자 설정

move_to_z()에 done_timeout_s=None 파라미터 추가. None이면 기존 30s 유지, 값 주면 그 값 사용. 시그니처 호환 유지.

2.3 ACS — FIX race 해소 + timeout 예외화

wait_in_position_all() 두 가지 수정:

  • 함수 시작 시 time.sleep(0.25) 강제 settle — polling 워커(200ms 주기)가 moving=True로 갱신할 시간 확보 → race 해소.
  • timeout 만료 시 silent return → raise TimeoutError(...) — 워커가 이상을 감지 가능.

회귀 검증: KinematicMoveWorker.run()은 이미 try/except로 감싸져 있어 새 예외도 안전하게 catch됨.

2.4 Mover 3종 — FIX timeout 주입

각 mover의 __init__에 move_timeout_ms 파라미터 추가:

  • MirrorMover: move 끝에 hub.pico_wait_motion_done(motor, timeout) 호출
  • KimmMover: hub.kimm_move_to_z(z, done_timeout_s=timeout/1000) 전달
  • AcsMover: ctrl.wait_in_position_all(timeout_ms=timeout) 전달

2.5 Scan Widget 3종 — ADD Move Timeout 스핀박스

UI에 Move Timeout (s) 추가 (기본 Mirror 10s / KIMM 30s / ACS 30s). get_move_timeout_ms() getter 노출 — 시그널 시그니처는 유지하여 기존 슬롯 호환.

2.6 main_tab — FIX mover 생성 시 주입

mover = MirrorMover(self._session_hub,

6. 검증 방법 (E2E)

  • 컴파일 sanity: python -m py_compile 14개 파일 → OK
  • Mirror 스캔:
    • 작은 delta(10 steps) 5포인트 → 정상 종료
    • 큰 delta(50000 steps) → 모터가 실제로 멈춘 후 snap, 블러 없음
    • 비현실적 delta + Move Timeout 2s → "Picomotor M1 move timeout after 2000ms" 에러
  • KIMM 스캔: Move Timeout 1s + 큰 Z 이동 → TimeoutError 라벨
  • ACS 스캔:
    • 정상: 모든 race 가려진 케이스도 초기 settle로 해소
    • Move Timeout 1s + 큰 거리 → TimeoutError 라벨

7. 미해결 / 후속 가능

  • Pico SDK가 만약 MotionDone 쿼리를 진짜로 노출한다면 위치 안정성 폴링보다 정확. 추후 SDK 확인 후 교체 가능.
  • PicoCard 폴링(300ms)과 wait_motion_done 내부 폴링(50ms)이 동시 호출되어도 Newport CmdLib8742는 내부 lock으로 안전하지만, 문제 발생 시 PicomotorController에 threading.Lock 추가 권장.
  • laser 모듈은 별도 — teus_client 리팩토링 제안 참조 (미구현).
